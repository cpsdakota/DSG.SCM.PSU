1 System Prerequisites

These playbooks require a Linux jump host with outbound HTTPS access to your Panorama/firewall management IPs and to the Palo Alto SCM API endpoints (paas-16.prod.panorama.paloaltonetworks.com, auth.apps.paloaltonetworks.com).

Supported distros

  • Ubuntu 22.04 LTS / 24.04 LTS (recommended)
  • RHEL / Rocky Linux / AlmaLinux 8 or 9
  • Debian 11 / 12

Install OS-level dependencies

bash — Ubuntu / Debian
# Refresh package lists and install build tools + Python
sudo apt-get update -y
sudo apt-get install -y \
  python3 python3-pip python3-venv python3-dev \
  build-essential libssl-dev libffi-dev \
  libxml2-dev libxslt1-dev \
  git curl wget
bash — RHEL / Rocky / AlmaLinux
# Enable EPEL (RHEL 8/9) and install Python + build tools
sudo dnf install -y epel-release
sudo dnf install -y \
  python3.12 python3.12-pip python3.12-devel \
  gcc openssl-devel libffi-devel \
  libxml2-devel libxslt-devel \
  git curl wget

# Make python3.12 the default python3
sudo alternatives --install /usr/bin/python3 python3 /usr/bin/python3.12 1

2 Install Python, pip & Ansible

Recommendation: use a virtual environment A virtual environment isolates all packages from the system Python and avoids permission issues on shared jump hosts. Both methods below produce identical results — pick the one that fits your client's policy.
What this does Creates an isolated .venv folder inside the project directory. All packages live there — nothing touches the system Python. You activate the venv before running playbooks (or point ansible_python_interpreter at it).
  1. Clone or copy the project to the jump host
    bash
    # Example: copy via SCP from your workstation
scp -r ./pso-ansible-dicksportinggoods-1445726 user@jumphost:/opt/ansible/

# OR clone from your Git repo
git clone <your-repo-url> /opt/ansible/pso-ansible-dicksportinggoods-1445726
  2. Verify Python 3.12 is available
    bash
    python3 --version       # must be 3.10+ ; 3.12 strongly recommended
python3.12 --version    # if installed as python3.12
  3. Create the virtual environment
    bash
    cd /opt/ansible/pso-ansible-dicksportinggoods-1445726

# Create .venv using python3.12 (adjust binary name if needed)
python3.12 -m venv .venv

# Activate it (must repeat this in every new shell session)
source .venv/bin/activate

# Upgrade pip inside the venv
pip install --upgrade pip setuptools wheel
  4. Install all Python packages
    bash
    pip install -r requirements.txt
  5. Verify Ansible is in the venv
    bash
    which ansible          # should show .venv/bin/ansible
ansible --version      # should show ansible-core 2.19.x
  6. Update ansible.cfg to use the venv interpreter

    Edit ansible.cfg and set the interpreter so Ansible always uses the venv Python even when the venv is not activated:

    ansible.cfg
    [defaults]
roles_path = roles
inventory  = inventory.ini

    Then in inventory.ini set the per-group interpreter:

    inventory.ini — interpreter line
    [all:vars]
ansible_connection          = local
ansible_python_interpreter  = /opt/ansible/pso-ansible-dicksportinggoods-1445726/.venv/bin/python
  7. Add a convenience alias (optional)
    ~/.bashrc or ~/.zshrc
    alias ans-activate='source /opt/ansible/pso-ansible-dicksportinggoods-1445726/.venv/bin/activate'
    Then just run ans-activate at the start of each session.
Root / sudo required System-wide installation writes to protected system paths. Make sure the user running playbooks either has sudo, or the system packages are installed by an admin first.
  1. Upgrade pip
    bash
    sudo pip3 install --upgrade pip setuptools wheel
  2. Install all Python packages system-wide
    bash
    sudo pip3 install -r requirements.txt
  3. Verify
    bash
    ansible --version
which ansible     # typically /usr/local/bin/ansible
  4. Set interpreter in inventory.ini
    inventory.ini — interpreter line
    [all:vars]
ansible_connection         = local
ansible_python_interpreter = /usr/bin/python3

4 Install Ansible Collections

Only one collection is required beyond what ships with ansible-core:

bash
# Install the Palo Alto Networks PAN-OS Ansible collection
ansible-galaxy collection install paloaltonetworks.panos:3.3.0
Version matters The playbooks were developed and tested against paloaltonetworks.panos 3.3.0. Using a newer major version may introduce breaking changes in module parameters. Pin with :3.3.0 unless you have tested a newer release.

Offline / air-gapped environments

If the jump host has no internet access to Ansible Galaxy:

  1. On a machine with internet access, download the collection tarball:
    bash — internet machine
    ansible-galaxy collection download paloaltonetworks.panos:3.3.0 -p /tmp/collection_tarballs/
  2. Transfer the .tar.gz file to the jump host (SCP, USB, etc.)
  3. Install from the local tarball:
    bash — jump host
    ansible-galaxy collection install /path/to/paloaltonetworks-panos-3.3.0.tar.gz

Verify collection is installed

bash
ansible-galaxy collection list | grep paloaltonetworks
# Expected: paloaltonetworks.panos   3.3.0

6 Configure Inventory & Credentials

inventory.ini

Edit inventory.ini to match the client's environment. Each firewall and Panorama host is listed with its management IP and credentials:

inventory.ini
[panorama]
panorama01 panorama_host=10.0.0.10 username=admin password=YOUR_PANORAMA_PASS

[firewalls]
fw01 panorama_host=10.0.0.20 username=admin password=YOUR_FW_PASS
fw02 panorama_host=10.0.0.21 username=admin password=YOUR_FW_PASS

[all:vars]
ansible_connection         = local
ansible_python_interpreter = /opt/ansible/pso-ansible-dicksportinggoods-1445726/.venv/bin/python
Credentials in plaintext Storing passwords in inventory.ini is convenient for initial testing. For production, move credentials to group_vars and encrypt with Ansible Vault (see next section).

group_vars/all/scm_credentials.yml

SCM playbooks read OAuth2 credentials from this file. It must contain:

group_vars/all/scm_credentials.yml (plaintext before encrypting)
scm_client_id:     "your-client-id-from-palo-alto-hub"
scm_client_secret: "your-client-secret"
scm_tsg_id:        "your-tsg-id"

ansible.cfg

ansible.cfg
[defaults]
roles_path = roles
inventory  = inventory.ini

7 Encrypt Secrets with Ansible Vault

Ansible Vault encrypts sensitive files so they can be stored safely in Git or on disk without exposing credentials.

  1. Create a vault password file
    bash
    # Write a strong password into the file — keep this file secret!
echo 'YourStrongVaultPassword123!' > .vault_pass
chmod 600 .vault_pass
    Never commit .vault_pass to Git Add it to .gitignore: echo ".vault_pass" >> .gitignore
  2. Encrypt the SCM credentials file
    bash
    ansible-vault encrypt group_vars/all/scm_credentials.yml \
  --vault-password-file .vault_pass
  3. Run any playbook with the vault password file
    bash
    ansible-playbook playbooks/check_bootstrap_status.yml \
  --vault-password-file .vault_pass
  4. Edit an encrypted file later
    bash
    ansible-vault edit group_vars/all/scm_credentials.yml \
  --vault-password-file .vault_pass

9 Playbook Reference

Playbook Type What it does Required -e variables
check_bootstrap_status.yml SCM Polls SCM for bootstrap status of on-prem devices. Can wait until a specific device reaches done. Optional: device_serial, wait_for_completion=true
force_bootstrap.yml SCM Triggers a forced bootstrap on a device in SCM. Pre-checks for device existence and skips if already bootstrapping. device_serial
push_config.yml SCM Pushes configuration from SCM to a firewall. Polls the job until completion and reports per-sub-job results. device_serial
move_device_folder.yml SCM Moves a device to a different SCM folder by traversing the folder tree and calling the move API. device_serial, target_folder
claim_devices.yml SCM Claims one or more VM-Series devices in SCM by serial number. vm_devices_list (JSON list of serials)
list_devices.yml SCM Lists all devices registered in SCM. —
enable_advanced_routing.yml PAN-OS Enables advanced routing on a firewall: checks state, configures, commits, reboots, waits (up to 12 min), and verifies. Optional: firewall_list
enable_sls_telemetry.yml PAN-OS Enables Strata Logging Service (SLS) forwarding and device telemetry. Optional: firewall_list
check_sls_telemetry.yml PAN-OS Health-check playbook for SLS and device telemetry. Produces a pass/fail summary report per firewall. Optional: firewall_list
remove_panorama_management.yml PAN-OS Removes Panorama management config and initcfg entries from a firewall and commits. Optional: firewall_list
pre_snapshot.yml Utility Takes a pre-change configuration snapshot of firewall state. Optional: firewall_list
post_snapshot_report.yml Utility Takes a post-change snapshot and generates a diff report against the pre-change snapshot. Optional: firewall_list
firewalls_backups.yml Utility Exports firewall running configuration backups to local files. Optional: firewall_list

Common run examples

bash — run examples
# Check bootstrap status for all devices
ansible-playbook playbooks/check_bootstrap_status.yml \
  --vault-password-file .vault_pass

# Check bootstrap status for a specific device and wait until done
ansible-playbook playbooks/check_bootstrap_status.yml \
  --vault-password-file .vault_pass \
  -e "device_serial=007957000834879" \
  -e "wait_for_completion=true"

# Force bootstrap a device
ansible-playbook playbooks/force_bootstrap.yml \
  --vault-password-file .vault_pass \
  -e "device_serial=007957000834879"

# Push config from SCM to a firewall
ansible-playbook playbooks/push_config.yml \
  --vault-password-file .vault_pass \
  -e "device_serial=007957000834879"

# Push config to multiple firewalls
ansible-playbook playbooks/push_config.yml \
  --vault-password-file .vault_pass \
  -e 'device_serial=["007957000834879","007957000834880"]'

# Move a device to a different SCM folder
ansible-playbook playbooks/move_device_folder.yml \
  --vault-password-file .vault_pass \
  -e "device_serial=007957000834879" \
  -e "target_folder=dick_prod"

# Enable advanced routing on specific firewalls
ansible-playbook playbooks/enable_advanced_routing.yml \
  --vault-password-file .vault_pass \
  -e 'firewall_list=["fw01","fw02"]'

# SLS & telemetry health check on all firewalls
ansible-playbook playbooks/check_sls_telemetry.yml \
  --vault-password-file .vault_pass

# Run with verbose output (-v, -vv, or -vvv)
ansible-playbook playbooks/check_sls_telemetry.yml \
  --vault-password-file .vault_pass -vv

10 Troubleshooting

ModuleNotFoundError: No module named 'pan'

Cause pan-os-python or pan-python is not installed in the Python interpreter that Ansible is using.
fix
# If using venv, make sure it is activated first:
source .venv/bin/activate

# Then reinstall:
pip install pan-os-python pan-python

# Verify ansible_python_interpreter in inventory.ini points to the venv:
ansible_python_interpreter = /opt/ansible/pso-ansible-dicksportinggoods-1445726/.venv/bin/python

Collection not found: paloaltonetworks.panos

fix
ansible-galaxy collection install paloaltonetworks.panos:3.3.0
ansible-galaxy collection list | grep paloalto   # verify

Vault decryption failure / bad password

fix
# Check the vault_pass file has no trailing newline issues:
cat -A .vault_pass     # look for ^M or unexpected characters

# Re-create it cleanly:
printf 'YourStrongVaultPassword123!' > .vault_pass
chmod 600 .vault_pass

Connection refused / timeout to firewall

bash — connectivity tests
# Test HTTPS to the firewall management IP:
curl -sk https://<FIREWALL_IP>/api/ | head -5

# Test HTTPS to SCM API:
curl -s https://paas-16.prod.panorama.paloaltonetworks.com | head -5

# Test SCM auth endpoint:
curl -s https://auth.apps.paloaltonetworks.com/oauth2/access_token | head -5

Wrong Python version used by Ansible

bash
# Check which Python Ansible will use:
ansible all -m debug -a "var=ansible_python_version"

# Override at runtime if needed:
ansible-playbook playbooks/check_sls_telemetry.yml \
  -e "ansible_python_interpreter=/opt/ansible/pso-ansible-dicksportinggoods-1445726/.venv/bin/python"

lxml import error on RHEL

bash — RHEL / Rocky
# lxml needs libxml2 / libxslt C libraries:
sudo dnf install -y libxml2-devel libxslt-devel
pip install --force-reinstall lxml
